# 副本助手 0.5.0-dungeon.4

本次更新现有文件后输入 `/reload`，再打开 `/wow-ai` 的“副本助手”。无需重启 AI 后台。首次安装完整插件时仍需重启游戏。

## 使用

- 按角色阵营过滤任务。部落只显示部落及双方任务，联盟只显示联盟及双方任务；对方阵营任务从清单、浮窗及各项统计中排除，每条保留任务显示明确阵营标签。副本内外遵循同一规则。
- 阵营依据任务 ID、明确阵营字段和 Forever 的种族限制核对，不按副本位置或名称猜测。阵营资料不足的未接任务暂不列入正常清单，只显示待核实数量，并阻止“已接齐”结论；若已在当前角色日志中则保留进度，注明资料待核实。
- 副本外打开“副本助手”，用“上一个 / 下一个”选择准备去的副本，立即按当前角色检查是否接齐。清单显示漏接、已接、已完成、前置未满足及条件待确认，并列出接取地点。本内/物品触发任务单列，不算进本前漏接。接取、放弃或交付任务后自动更新；“进本前检查”按钮也可手动刷新。
- 进入副本后，小浮窗检查已收录任务：漏接、进行中、本内/物品接取、条件待确认。详情显示接取 NPC/地点、完成方法、前置链和实时目标。
- 接任务、交任务、放弃任务以及目标变化会更新。完成目标的任务从任务浮窗移除，全部处理完后任务浮窗自动关闭；完整清单仍保留可交付状态。
- 首领成为目标、鼠标指向单位、可见姓名板或首领单位时，自动显示其掉落。首领战开始事件也可触发。按副本内中英文名称精确匹配，每次进本每位首领提示一次；失败的首领战允许再次提示。离开副本关闭浮窗。
- 浮窗可拖动并保存位置，两个关闭按钮分别控制任务和掉落。“浮窗：开/关”控制自动提示；主页面始终可手动查看。副本外可切换副本检查任务和查看首领；实际进本后自动切到当前副本，出本回到原先选择。副本外检查不会触发进本浮窗，也不调用 AI。
- 当前天赋自动读取，按投入最多的天赋树选取比较规则。支持旧式天赋接口及 Forever 的 `C_SpecializationInfo.GetSpecializationInfo` 第七项 `pointsSpent`。未投入、平点或不可读取时，不断言升级。装备、天赋改变时自动刷新。
- 金色“预计升级”是对当前装备的基础属性估算；绿色为适用或需额外比较。说明列出替换装备及评分差。悬浮掉落条目可查看游戏物品说明。
- 野外任务助手继续跳过副本任务。副本助手不自动接/交任务、不自动装备或参与拾取分配，不注册受限战斗日志事件，不产生自动 AI 请求。

任务条件来自 EverythingQuests 的 Forever 数据，覆盖等级、职业、种族、已完成、任一/全部前置、分支及父任务。缺失条件、专业或声望未核对时显示待确认，不计作确定漏接。未收录副本明确提示无法判断接满。接齐的措辞限定为“已收录且当前可接的任务”，不保证全部隐藏、新增或职业任务。

部分拾取物触发任务只能在副本内取得，不要求玩家进本前接满。任务完成浮窗自动收起不等于自动交付。若另有漏接或本内任务，浮窗继续显示剩余条目。

无法读取不可见、超出客户端范围的首领，也没有可靠的全副本实时距离信息；不会假装按地形距离预测首领。需要目标/鼠标/姓名板/首领单位之一可读，或首领战事件触发。中文名称与服端不同可能影响匹配，可在页签手动选择首领查看。

护甲和武器按经典职业使用范围过滤，需求等级和职业限制也参与检查。特殊新增职业使用规则需后续适配。只在候选和当前装备的客户端属性均可读取时标记预计升级；未缓存物品会请求加载并随后刷新。基础评分覆盖主要属性、法强、治疗、攻击强度、护甲等；法师按当前主系区分火焰/冰霜/奥术伤害。权重为本插件练级启发式，不是 BIS 清单或伤害模拟。

戒指比较两个槽位中较弱的一件；同款唯一物品、唯一类别限制另行提示。双手武器与主副手合计比较；从双手改成单手/副手要求整套比较。物理武器速度、双持、饰品、触发/使用/套装效果、未解析等级属性均采用保守提示，不把物品等级高视为必然升级。未知的特效价值、命中上限、附魔与套装联动并未完整模拟。

## 来源与重建

- `dungeon-faction-audit.json` 列出全部 81 条记录的逐项阵营和证据。目前 35 条联盟、30 条部落、7 条双方、9 条资料不足。`tools/dungeon-factions.js` 区分明确的种族掩码 0（无限制）与缺失数据；来源冲突不强行归类。9 条待核实为 5724、96395、96403、96393、92422、6981、1144、2904、2945。本次也复查了 [An Ancient Grudge](https://wowforevertalents.com/quests/an-ancient-grudge-96395/)、[Important Heirlooms](https://wowforevertalents.com/quests/important-heirlooms-96403/)、[Old Ironforge Incursion](https://wowforevertalents.com/quests/old-ironforge-incursion-96393/) 和 [The Wrath of Rath'mael](https://wowforevertalents.com/quests/the-wrath-of-rath-mael-92422/) 的客户端资料页；这些页面未明确给出阵营限制，未凭地点或交付 NPC 补猜字段。
- 用户现有资料归档 `miniapp/research/2026-09-28/wowf-dungeons-zh.json`（来源 [wowf.io](https://wowf.io/zh/dungeons/ragefire-chasm)）。保留 `site`、`classic`、`unspecified` 来源分级。
- 用户现有 2026-09-28 物品归属核对表 `miniapp/miniprogram/data/loot.js` 优先覆盖首领归属；不改写原资料项目。归属未知不挂到具体首领。
- [EverythingQuests](https://github.com/wheelbarrel00/EverythingQuests)，固定版本 `9c1ce1e44238d8c6c8ca36d8f49836fde70b564f` 的 `Data/QuestAvailable_Forever.lua`，MIT；许可在 addon/WoWAI/THIRD_PARTY.md。
- [怒焰裂谷任务资料](https://wowforevertalents.com/dungeons/ragefire-chasm/)及[归还背包 5724](https://wowforevertalents.com/quests/returning-the-lost-satchel-5724/)用于核对本内物品后续任务。
- 游戏 API 对照 [Blizzard UI 的 SpecializationInfo 定义](https://github.com/Gethe/wow-ui-source/blob/classic/Interface/AddOns/Blizzard_APIDocumentationGenerated/SpecializationInfoDocumentation.lua)及 Item API；运行时安全读取与缺失降级。

重建：`node tools/build-dungeon-data.js <miniapp目录>`。构建工具只解析 JSON 和 Lua 字面量，不执行外部 JS/Lua。输入 SHA-256 和逐副本覆盖数见 `dungeon-data-receipt.json`。

## 验证

自动检查包括任务接取条件、任务完成关闭、进入/离开、首领重复提示与失败重试、天赋切换、职业不可用装备、缓存缺失、主副手、唯一戒指、第四页签与聊天草稿隔离、真实资料引用一致性。游戏内实测仍需用户在重启后进入一个副本，验证当前客户端的实际单位名称和物品数据返回。

## 0.5.0-dungeon.4 修复

- 优先读现代天赋点数；旧接口返回名称但缺少点数或天赋页数为零，不再阻断新接口。兼容表式返回值、旧式 ID/名称/第五项点数，以及逐项天赋等级求和。部分树不可读、同点或未投入时不强判主系。AI 游戏上下文复用同一份读取。
- 天赋暂缺时仍显示职业属性指引；仅有参考属性时明确等待缓存，不声称升级。名称已缓存而属性/图标缺失也会请求物品数据，限制每项最多 3 次、间隔 10 秒。
- 列表与首领浮窗直接显示物品图标和品质边框；图标未就绪显示问号，缓存事件后刷新。切回任务清单会隐藏复用行的图标。鼠标悬浮仍显示物品提示。
- 189 项功能测试和 4 项编码测试通过；当前客户端内的天赋值与更新后布局尚待实测确认。
